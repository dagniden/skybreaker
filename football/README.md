# Football: публичная история матчей и реплеи

Приложение Django принимает JSON версии 1 из Godot, хранит метаданные в БД,
снимки в приватном файловом каталоге. После загрузки матч сразу появляется в
**публичной истории**, без регистрации. Это намеренно не приватные записи по
секретной ссылке. Сетевые матчи и тренировки пока не записываются.

## Адреса

- `https://football.sky-breaker.ru/` — история матчей, по 20 на странице.
- `/football/` — та же история на любом разрешённом домене, удобно локально.
- `/football/replays/<id>/` — Canvas-плеер: перемотка, скорость, счёт, голы.
- `POST /api/football/replays/` — загрузка с `Authorization: Bearer <отдельный токен>`.
- `GET /api/football/replays/<id>/` — публичные данные, без ключа.
- `/admin/football/replay/` — управление записями для администраторов.

`FootballHostMiddleware` переключает корневую страницу **только** для имён из
`FOOTBALL_SITE_HOSTS`; главная страница основного сайта не меняется.
Добавление домена в этот список не заменяет проверку `DJANGO_ALLOWED_HOSTS`.

## Локальная проверка с Godot

В `.env` Django добавьте отдельный **тестовый** токен:

```ini
FOOTBALL_REPLAY_UPLOAD_TOKEN=local-replay-test
```

Из корня Skybreaker:

```powershell
.venv/Scripts/python.exe manage.py migrate
.venv/Scripts/python.exe manage.py runserver 127.0.0.1:8000
```

В `playtest.local.cfg` проекта Football добавьте секцию, не изменяя `[connection]`:

```ini
[replays]
server_url="http://127.0.0.1:8000"
upload_token="local-replay-test"
```

Перезапустите Godot, F5, сыграйте с ботами и нажмите «Сохранить и загрузить
реплей». Откройте `http://127.0.0.1:8000/football/` — матч появился в истории.
Для проверки именно корня `http://127.0.0.1:8000/` временно задайте
`FOOTBALL_SITE_HOSTS=football.sky-breaker.ru,127.0.0.1,localhost`.

Не публикуйте `.env`, `playtest.local.cfg` и их резервные копии. Токен загрузки
не должен совпадать с ключами relay, транскрипции, Django SECRET_KEY.

## Production

1. В `.env` добавьте `football.sky-breaker.ru` в `DJANGO_ALLOWED_HOSTS` и задайте
   отдельный `FOOTBALL_REPLAY_UPLOAD_TOKEN`. Пример — в `.env.example`.
2. Задайте `FOOTBALL_REPLAY_ROOT` постоянным приватным каталогом, например
   `/var/lib/skybreaker/football-replays`. Пользователь Gunicorn (`deploy` в текущей
   схеме) должен иметь права записи. Каталог нельзя публиковать как `/media/`.
3. Выполните штатный deploy: `migrate`, `collectstatic`, restart Gunicorn.
4. В существующем блоке Caddy для футбольного домена замените маршрутизацию по
   образцу `football/Caddyfile.example`: WebSocket Upgrade → relay:8765,
   обычный HTTP → Django:8001, `/static/` → collectstatic. Проверьте конфигурацию
   перед reload. Не трогайте блок основного сайта и не создавайте дубли домена.
5. Ежедневно запускайте от пользователя приложения (cron/systemd timer):
   `python manage.py cleanup_football_replays` с теми же настройками окружения.
6. Обновите `[replays]` в конфигурации клиента и пересоберите тестовую игру.

HTTP-сервис реплеев aiohttp:8766 больше не нужен для новых клиентов. Если он уже
был развёрнут вместе с relay, можно пока оставить его работающим, но Caddy больше
не направляет туда HTTP. **WebSocket-relay остаётся нужен для сетевой игры.**
Старые JSON автоматически не импортируются; это отдельная операция переноса.

## Ограничения и безопасность

- Формат: 12 игроков, до 10 минут/12002 кадров и 12 МиБ на запрос.
- Данные строго проверяются: времена, координаты, составы, владение и счёт;
  неизвестные поля удаляются. Реплей не содержит выполняемого игрового кода.
- По умолчанию 200 записей/256 МиБ; при заполнении загрузка возвращает 507.
- Срок хранения 30 дней. Просроченное сразу скрыто из истории и недоступно по
  прямой ссылке; файлы удаляет cleanup-команда. До очистки они занимают квоту.
- 20 попыток загрузки за 10 минут суммарно. Бюджет и блокировка находятся в БД,
  поэтому не сбрасываются от смены Gunicorn-воркера. Для production используется
  PostgreSQL. SQLite годится для локальной проверки; при конкурирующих записях
  возможен 503, который клиент может повторить.
- JSON-файлы отдаются Django с проверкой срока, не открытым media URL. Удаление
  через admin/ORM удаляет файл после успешного commit. Сбой процесса между
  файловой записью и commit может оставить orphan-файл; хранение на диске и БД
  не является общей атомарной транзакцией. Не удаляйте файлы/строки вручную.
- Встроенный в клиент токен можно извлечь; это защита плейтеста, не аккаунты.
  Для широкого запуска нужны пользовательские токены/квоты и внешние лимиты
  соединений/таймаутов на reverse proxy. Просмотр намеренно публичный.

## Тесты

```powershell
# Использует отдельную тестовую базу, не существующие данные:
$env:DATABASE_URL = "sqlite:///:memory:"
.venv/Scripts/python.exe manage.py test football
.venv/Scripts/python.exe manage.py makemigrations --check --dry-run
```

В репозитории Football: `tests/replay_smoke.gd` проверяет запись и при аргументе
`--replay-test-url=http://127.0.0.1:8000` — реальную загрузку в тестовый Django
с токеном `local-replay-test`.
